# W1-SAVE-AI — a saved enemy came back with its mind removed, and boot-check never noticed

**Dispatch:** `orchestration/NEXT-DISPATCH.md` §Q0. Found by the W1-16 r2 critic, in a file that
was not W1-16's. **Commit of the fix:** the source landed in `692b6aa` (a neighbour's commit swept
it — see §7), verified again at `be9af27`. Every figure below is a claim about that tree.

Reproduce: `node tools/check-save-shape.mjs --verbose`, `node tools/harness/boot-check.mjs`,
`node tools/harness/save-ai-consumption.mjs`. The JSON artifacts under `reports/w1-save-ai/` are
deliberately unversioned (`reports/.gitignore`) and are regenerated by those three commands.

---

## 1. The defect, reproduced on the shipped tree

`save/fight.js`'s `SKIP` list omitted `ai`, so `saveActor(ctl)` walked the live `SoulsAI` with the
generic encoder and `loadActor` assigned the resulting plain object back over the instance.

One browser, `loadState('default')` + 8 steps, on a naturally populated province body
(`pop-0027-infantry-0` — not a fixture I spawned):

| | before the repair | after |
|---|---|---|
| `ctl.ai` constructor across `saveRoundTrip()` | `SoulsAI` → **`Object`** | `SoulsAI` → `SoulsAI` |
| `typeof ctl.ai.step` after the load | **`undefined`** | `function` |
| `stepFrames(1)` after the load | **throws `this.ai.step is not a function`** | frame 1 |
| the AI record in the save | **81,892 bytes** | **302 bytes** |
| the whole save | 194,161 bytes | **112,590 bytes (−42%)** |
| `saveRoundTrip()` diff | 2 paths | 1 path |

The 81,892 bytes are the reason this is not a small defect: behind `ai.b` the encoder dragged in
the whole `CombatBody`, behind `ai.stat` the statblock and behind `ai.cfg` the entirety of
`ai.json`. **42% of every save file was a copy of the rulebook, per enemy.**

**Why it was invisible.** Every agent boot-checks before it measures, and boot-check did not step.
The engine constructed, the harness answered, and a frame came out — all green — because the
failure is on the frame *after* a load.

## 2. The fix, and why not `SKIP`

Adding `ai` to `SKIP` would have been a second defect, not a fix. `EnemyController._idleBehaviour()`
guards its whole souls branch with `if (this.ai)`, so a skipped `ai` restores as `null` and the
enemy **stops thinking without throwing anything at all** — measured, §5. That is the same shape as
`post` in `save/state.js`, which restored quest-givers invisibly inside locked cellars.

So the split is made by the class that knows it, following the `saveState()`/`loadState()` contract
`Rig` already had in `combat/skeleton.js`:

* **machinery** (`b`, `stat`, `cfg`, `A`, `omega`, `sightR`, `walk`, `sprint`, `leashHard`) — every
  one a pure function of (statblock, `ai.json`), every one rebuilt by the constructor;
* **behaviour** — everything else, enumerated from the live object so a field added next round is
  carried without anyone remembering: state and its clock, gait, strafe choice, the group attack
  token, four timers, the no-LOS clock, RI-AI01 M4's `commitIntervals` cadence history, and
  `anchor`, the leash origin.

Nine AI frame stamps are now rebased against the frame `loadState()` resets to, using
`save/fight.js`'s own `relStamp`/`absStamp` rather than a second copy of the sentinel rule.

And the rule is general, not a case: **`saveActor` never walks a class instance again.** It carries
it through its own `saveState()` or refuses it and names it in `__unsaved`; `loadActor` never
assigns a plain object over a live one.

## 3. `hash_equal: false` — half fixed, half named

Two paths differed. One was mine and is gone; one is not mine and is precisely located.

* **`fight.enemies` — fixed.** `moveKeyOf()` resolves a move object to its *table key* by identity
  (`table[k] === m`). Nested under `ctl.ai.b.moves` the save carried *copies*, so on the re-save
  identity failed and `moveKeyOf` fell back to `m.id` — `roll` where the first save had written
  `roll_LIGHT`. It went with the `ai` subtree.
* **`death.last_grounded` — NOT MINE, NOT FIXED, and it is a real defect.**
  `game/src/engine.js:7182` runs on every load:
  `if (this.death.active) this.death.lastHp = 0; else { this.death.lastHp = null; this.death.lastGrounded = null; }`
  — one statement after `DeathSystem.restoreInFlight()` (`sim/death.js:98`) restored `lastGrounded`
  from the blob that `save/state.js:336` wrote. It is the D3 fall-rule respawn point, so **a player
  who loads a save loses where they last stood on solid ground.** This is exactly the shape the
  comment four lines above it describes about `lastHp`. Left alone because `engine.js` has eight
  live claimants and was `MM` (staged *and* unstaged neighbour edits) for this entire run, so
  `git commit --only game/src/engine.js` would have carried them.

## 4. Making the class unshippable — `tools/check-save-shape.mjs`

Takes a prototype-method census of the object graph before the save and after the load and asserts
**every restored object which had methods still has them.** No browser, no engine, ~100 ms: it
imports `save/fight.js`, `combat/ai.js` and `combat/enemy.js` and drives them against the shipped
`ai.json`. Wired into `tools/check-data.mjs`, which `.githooks/pre-commit` already runs.

Armed only after being shown both ways (RULES 13):

* **silent** on the repaired tree — 8 assertions pass;
* **red** against the real pre-fix source, served from a scratch copy: **15 findings**, including
  the defect itself and *five frame stamps that were never being rebased and that nobody had
  noticed* (`strafeUntil` 4030 where 30 was correct, `cooldownUntil` 4090, `stateEnteredF` 3989,
  `tokenSinceF` 3960, `lastCommitF` 3936 — a 4,000-frame cooldown on every load).

Its instrument deliberately does **not** import `liveObjectName` from the code under test. The
first draft did, and the pre-fix run died as a `SyntaxError` instead of producing a finding — a
check that imports its definition of "broken" from the thing it is testing cannot fail when that
thing is replaced by an older one. `--self-break` prints the red on demand.

## 5. `boot-check` now steps

One `guard_legion`, one step to build its AI, `saveState()` → structural clone → `loadState()`,
then step again. Armed (`STRICT_STEP`) on the same terms as the rendered-frame assertion above it.

**Cost, measured and then trimmed rather than assumed.** `saveRoundTrip()` cost **3,110 ms**,
because on top of the load it takes two `getStateHash()` calls (a full `saveState()` each) and a
`stateDiff`, none of which this arm needs. `saveState` → clone → `loadState` is the same seam for
**622 ms**: spawn 1 ms, first step 139 ms, saveState 17 ms, clone 18 ms, `loadState` ~900 ms under
load, final step 15 ms. The `loadState` cost is the thing under test and is not reducible.
Whole check: 27.9 s.

**Proven red two ways, because there are two ways this defect presents:**

| build | `harness_responsive` | `rendered_a_frame` | `stepped_after_a_load` | exit |
|---|---|---|---|---|
| repaired | true | true | **true** | 0 |
| real pre-fix source | true | true | **false** — `this.ai.step is not a function` | 12 |
| the naive `ai`-in-`SKIP` fix | true | true | **false** — `a live AI was lost across the round trip: 2 before, 0 after` | 12 |

The middle column is the point: **every pre-existing arm of boot-check stays green in all three
rows.** And the third row is why the arm counts live AIs rather than only catching an exception —
the naive fix throws nothing whatsoever.

It stays quiet where it cannot know: no verbs, no combat state, or no live AI on the floor, and
`stepped_after_a_load` is `null` and nothing is claimed either way.

## 6. CONSUMPTION (RI-MTH07) and RULES 6, four arms

World-side consumer, named and driven rather than asserted: `EnemyController._idleBehaviour()` →
`SoulsAI.step()`, which writes `b.pos`, `b.yaw`, `b.state`, `b.speedMps` and emits `enemy_state`.
`step()`'s **first** decision is the T25 leash, taken against `this.anchor` — a field that lives
nowhere but on the AI and that a load can only get from this save.

| arm | what | result |
|---|---|---|
| **A** baseline | load unchanged, 240 steps | `IDLE`, moved **0.000 m**, end (2771.5, 5013) |
| **B** perturb | move the *saved* `anchor` 300 m, load that | **`LEASH_RETURN`**, moved **8.672 m**, end (2765.368, 5006.868) |
| **C** null control | perturb `ai.s.yawRate`, a trace output assigned every frame before anything reads it | **byte-identical to A**, 0.000 m |
| **D** delete-the-fix | same script against a served copy of the pre-fix source | fixture sound (`ai_live_before_save: true`), then **`the AI came back without step()`**, exit 2 |

B ≠ A says the state is **read**, not merely carried — the sixteen-subsystem failure this project
keeps finding. C = A says B is not noise: without it, "the control looked like a clean negative
result" is how W1-04 lost fifteen walks. D says the fix is not inert and **the teardown bites** —
it does not exit before exercising the thing under test, it reproduces the original failure.

Which of RULES 6's three shapes this is, stated: **a single fix.** Cutting it alone returns the old
failure. Not two guards, and not an inert fix.
