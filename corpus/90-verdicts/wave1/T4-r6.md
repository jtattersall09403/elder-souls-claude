### Why the builder's arms could not have measured what they named

`tools/lib/cli.mjs:11` derives `REPO_ROOT` from **the script's own location**, and
`tools/lib/browser.mjs` `resolveEntry()` serves `REPO_ROOT/game`. An arm is isolated **only if it is
run through the clone's own copy of the tool**. `t4-r2-measure.mjs:296` records
`git rev-parse HEAD` with `cwd: REPO_ROOT` — so the manifest states which tree actually ran.

All four of the builder's manifests record **a live sibling's HEAD**, timestamped to the minute each
arm ran:

| arm | recorded commit | what it actually is |
|---|---|---|
| live | `22d6fb39` | a gitignore commit, 17:15 |
| baseline | `f42cb9be` | F10 r9, 17:24 |
| attrib | `0a67808f` | F10 r9 status, 17:39 |
| **pin5** | `dffbd4bc` | F10 r9 critic, 17:44 |

None is HEAD. None is the pin. Proven by construction, this session:

- a real `control-clone` resolves `REPO_ROOT` into `/tmp/…` where `git rev-parse` **throws**, so the
  tool records `commit: "unknown"`;
- a real `git worktree … 76cd4848` records `commit: 76cd4848…`.

So every arm ran the **shared live tree**, which is exactly why four "different" arms agreed to four
decimal places on all seven screens.

> **The general lesson.** Four arms agreeing to four decimals is not convergent evidence — it is the
> signature of four runs of the same thing. `HAZARDS` §11 says freeze the arms by construction; the
> missing half is **verify the freeze held**, and here that was free, because every manifest already
> carried the commit it actually ran.
