## 2. The player's path and the harness's path differ by one field, and the difference is fatal

**`Engine._titleApply('new')` — the row the title's `New` commits to — calls `censusBegin({})`.**
`Census.spec.race` is set by exactly one function, `Census.observe(race)`, called from exactly one
place, `censusBegin` when `opts.race` is present. So on the player's path race is **never
observed**, and `Census.answer()` at `writ.race-observed` reads:

```js
if (!this.spec.race) throw new Error('census: race must be observed before the scene reaches the desk');
```

`tools/journey/census-newgame.mjs` (written for this verdict; node-side, no browser) walks the
graph both ways:

```
the player's path — censusBegin({}), nothing observed:
    STOPPED at writ.race-observed: census: race must be observed before the scene reaches the desk
    nodes reached: hold.hatch-name -> writ.race-observed

the harness's path — censusBegin({ race: 'saxhleel' }):
    COMPLETED: the scene completed
```

**CONSUMPTION (`RI-MTH07` / `ARBITRATION` §3), on the round's most load-bearing claim.** The model
is `Census.spec.race`; the world-side consumer is `Census.answer()` at `writ.race-observed`, which
composes the scribe's misread line and gates every later node, and downstream
`composeCharacter()` → the writ → what NPCs say. Perturbed one field, held the rest:

| `observe(race)` | Outcome |
|---|---|
| `null` | stops at `writ.race-observed` |
| `dunmer` | completes |
| `khajiit` | completes |
| `saxhleel` | completes |

`coupling 1`. **Null control** (same inputs twice) identical. **Delete-the-fix**: the two arms
differ, so the check is not inert.

**The throw is caught.** `_censusApplyPending()` catches it, emits `census_refused`, and puts the
reason on `censusSurface.refusal`, which the surface draws. So it is not a crash — it is a
**soft-lock in which the Warden-Scribe says `race must be observed before the scene reaches the
desk` to the player, in the dialogue panel, forever.**

**And the corpus's own instrument cannot see it.** `tools/journey/journey-run.mjs` — `A-JRN1`, the
driver `RI-JRN01` names in its own command line — opens the scene at line 955 with
`handle.hOpt('censusBegin', {})`, the same empty options, and then walks it with
`try { await handle.h('censusAnswer', answer); } catch { break; }`. **A bare `catch { break; }`.**
The one tool written to drive this journey reproduces the player's defect and then swallows the
exception that proves it. That is `RI-JRN01` How-we-lose #15 — *the instrument is blind and the

## 3. You cannot type your own name

This is the one I did not expect and it is the reason a real-input probe was worth writing.

`game/src/input/real.js` `attach()` handles a `keydown` in this order — movement map, then control
map, then text:

```js
const dir = this.moveCodes[e.code];     if (dir)    { ...; return; }   // W A S D, arrows
const action = this.controlMap[e.code]; if (action) { this._down(...); return; }
if (this.onTextChar) { ... this.onTextChar(e.key); }                   // text entry, LAST
```

So a letter bound to a button never reaches the text field. From
`game/data/input/profiles.json` alone, **before touching the browser**, that is:

- **14 of the 26 letters: A C D E F G M R S T V W X Z**
- digits **1 2 3 4**
- **`Space`**, which is `roll` — you cannot put a space in your name
- and **`E` is `interact`**, which does not merely drop the character: it **commits the node**

`tools/journey/name-entry.mjs` types two names through the real listeners, one character per fixed
frame so that frame rate is not a variable, and reads back what the census recorded:

| Typed | Predicted from the bindings | Recorded |
|---|---|---|
| `Hio-Junnilo` (no bound characters) | `Hio-Junnilo` | **`Hio-Junnilo`** — verbatim |
| `Silt-Under-Salt` | `il-Un-l` | **`il-Un`**, and *the scene committed itself mid-word* at the `e` in "Under" |

Two arms differing only in which letters were pressed. The control round-trips exactly, so the
typing path itself is sound and the binding shadow is the whole cause. In the slower rAF-driven
play run the same name came back as **`il-Un-l`** — the prediction character for character,
because at 2.9 fps two more characters landed before the fixed step latched the `interact` edge.

`MW/EXCHANGE` row 1 is *"a name, typed — Jiub repeats it and remarks on it."* Here the name typed
is not the name recorded, and typing an `E` ends the conversation.

2. `writ.stamp` — *"Do not lose it. The door behind me is the one you want. **Past it, no one

The bolded clause was **added this round** — it is not in the parent of `e7ed252` — and it is a
tutorial. Not a pop-up, not a banner, not a HUD string: a good sentence in a good voice from a

whose own path says the world does not explain itself, and it is the only such sentence in the
opening. Morrowind's comparable line is Sellus Gravius giving you a package and a name in Balmora
— a **task**, not a **mechanic**. *"So ask them what they do"* is a mechanic.

I record it as a named blemish and not as a hard fail: HF3 is about tutorial pop-ups and objective
banners, and this is neither. It costs `RI-JRN01`'s Restraint block a point, and the remedy is to
delete one clause and let the nine root topics the stamp grants be discovered.

**One more thing that is drawn and should not be.** The HUD — a health bar, a stamina bar, a purse
reading `5`, the stance readout `LIGHT` and the equipped spell `Spark-Dart` — is painted **on the
title screen**, at first launch, before any character exists, and stays up through the barge hold.
It is visible in `docs/shots/2026-08-08-w1-26-r2-01-title-first-launch.png`. Not a marker, so not
HF4; but a first-launch title that shows a stranger's health bar is a `journey.firstlaunch.flow`
