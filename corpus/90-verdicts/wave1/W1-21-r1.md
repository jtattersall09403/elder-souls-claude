## 1. The question this piece exists to answer, and the answer

`docs/PLAN.md` §3: *"RI-UIX02 is the enforcement point for the most-cited arbitration rule in
the corpus."* The rule is AR-2 — *did any Souls-flavoured convention contaminate the world?* —
and the convention it is chiefly about is the objective marker.

The brief told me to try to get a marker onto the map and report whether I could.

**I could.** Not through a quest hook, and not through the routes the builder's own
`tryPlaceMapMarker` tries — those are all correctly closed. Through the save file:

```
saveState()
  → world.discovery.cells   := an all-ones raster
  → world.discovery.places  := every id in game/data/world/pois.json  (42)
loadState(forged)
```

The live-world load audit **dropped nothing**. The map then drew **42 place squares, 35 of them
for places the body had never stood in**, over a **fully rendered province** — and the screen's
own compliance report said `places_drawn: 42, places_discovered: 42` and went green.

`AMENDMENT-W1-MAP-01` §3a makes two of those a hard fail in the same sentence: *"a square for a
place the player has not stood in; terrain rendered where the player has not been."*

That is the finding. The rest of this verdict is why nothing in the build could have caught it.

## 3. The marker, in detail

### 3.1 The routes that are closed, and they are genuinely well built

I want to be plain that the map's design is good and mostly holds. `Discovery` keeps its state
in `#private` fields, freezes the instance, and exposes `observe()` at **arity 0** so that there
is no parameter in which a caller could name a place. `openMenu('map', {place})` throws with a
written reason rather than ignoring the argument. `openMenu('minimap')` throws. `roads.json` is
not imported by the map screen. My pass-A checks confirmed all of it independently:

```
ok  A1  journal cannot reach map and map cannot reach journal
ok  A2  map screen declares no forbidden kind
ok  A3  no element carries a quest/objective/giver/target/route/travel identity
ok  A4  no numeral is drawn on the map
ok  A5  no square drawn for a place the body has not stood in   (14 drawn, 14 stood in)
```

### 3.2 The route that is open

`Discovery` has a **fourth** mutating method the header does not mention and the amendment's
arity argument does not cover:

```js
restore(blob)          // arity 1. Clears the raster, refills it, and rebuilds the place list
                       // FROM IDS THE CALLER SUPPLIES.
```

The file's own header says *"`observe()` … **the only mutator**"* and *"every mutating method on
this object has arity 0."* Both sentences are false as written. `restore()` is the one method in
the design that does exactly what S35 forbids — it names places — and it is the one method
`tryPlaceMapMarker` never tries.

It is defended, but by a check that cannot work. `restore()` accepts a place only if *the raster
in the same blob* shows that place's cell revealed. `map-probe.mjs` L3 tests this by forging the
**place list** and leaving the raster honest, so the places are dropped and L3 passes. But an
attacker who can write one field of the blob can write the other. Forge both and the
corroboration is a fixed-point test on its own input:

```
F1  FAIL  dropped=[]  places 7 -> 42,  revealed 2527 -> 42846
F2  FAIL  42 squares drawn, 35 phantom:
          soulrest, ixtaxh-tzil, nine-mud, the-weeping-ford, xal-ithix,
          kiln-camp, sunken-barrow, mudwater-landing, …
F3  FAIL  places_drawn=42  places_discovered=42  stood_in=7
```

`F3` is the part that should worry a reader most. The screen's compliance report is internally
consistent and completely wrong, because both of its numbers are read off the same forged model.

### 3.3 The check that reads a register instead of the object

`AMENDMENT-W1-MAP-01` §3b tells a critic to verify the arity claim *"from the running object so
a critic does not have to take the source file's word for it"*, and the build obliges with
`getUIState().map.mutator_arities`. Here is what that field is:

```js
mutator_arities: { observe: …observe.length, suspend: …suspend.length, resume: …resume.length }
```

A **hand-written literal of three names**. Enumerating the prototype instead takes four lines and
finds the fourth:

```
G1  FAIL  reported=[observe,suspend,resume]
          actual mutators=[observe,suspend,resume,restore]
          missing from the report=[restore]
G2  FAIL  restore/1
```

This is the same shape three neighbouring pieces have now been caught by, and it is worth naming
as a pattern rather than as an incident: **a compliance report assembled from a list can only
ever report the things whoever wrote the list already thought of.** The whole value of putting
the structural evidence in `getUIState()` was that it would be read off the running object. It
is not. It is read off a literal, and the literal is missing precisely the member that breaks
the claim.

### 3.4 Nothing in the piece looks at the map at all

The map is the surface S35 defines by its refusals. Here is the coverage of every AR-2 and
fidelity detector W1-21 ships:

| Instrument | What it visits | Map? |
|---|---|---|
| `ui-layer.mjs` (K2, pixel sweep) | 8 viewpoints: world, combat, inventory, journal, book, levelup, sheet, spells | **no** |
| `ui-metrics.mjs` (RI-UIX06) | `inventory,journal,book,levelup,sheet,spells` | **no** |
| `ui-forbidden.mjs` (RI-UIX01 §B) | `inventory, journal, sheet, spells` | **no** |
| `marker-diff.mjs` (K3/K4) | quest-state differential, no menu open | **no** |

Five detectors, zero visits. The only thing that has ever looked at the map screen is
`map-probe.mjs`, which the map's own builder wrote — and RI-UIX02 K6 requires **≥14 viewpoints**
against the 8 that exist, so the coverage check fails on its own terms too.

## 4. The paused screen still does not redraw — the half of the fix nobody looked at

W1-MAP found that **no press on a paused screen redrew anything**: `UISystem.build()`'s cache key
was `frame + mode + touch`, every menu pauses the world outside combat, and
`engine._step()`'s paused branch never calls `stepOnce()` — so the frame is frozen and the key is
constant for the life of the screen. The fix was to append `focusSignature(mode, focus)`.

That fix is real and I confirmed it. It also only covers half the problem, because **the model
can change on a paused frame without the focus moving**. `Engine._afterStep()` runs on paused
frames and applies `ui.pending` there — `use`, `transfer`, `level` and `equip` all commit while
the world is stopped. None of them touches `focus[mode]`. The cache key has no term for any of
them.

Measured in **pixels**, through the real input pipeline (`queueInputs` at `f: 0`, because a
frozen frame can never satisfy `f ≥ 1`), with the control run first:

```
H0  ok    CONTROL: a focus move on the paused screen    → 55,656 pixels change
H1  ok    using an item changes the model                → black-water-draught 3 → 2
H2  FAIL  and the player sees it                         → 0 pixels change
H3  FAIL  reopening the screen is not what repaints it   → 102 pixels change on reopen
```

A player selects a potion, presses use, and **the screen does not move a single pixel**. The
potion has gone from the simulation. The row still says `×3`. It says `×3` until they close the
inventory and open it again, at which point it says `×2`.

This is the third instance of one family of defect in this interface and the second time it has
been shipped after being fixed. The lesson the first two rounds have already paid for is that a
frozen frame counter is not a safe cache key; the lesson still outstanding is that **`focus` is
not the only thing that changes while the world is stopped.**

## 5. RI-UIX02 K1 is red at HEAD, and the headline is stale

`orchestration/status/W1-21.json` records *"RI-UIX02 K1 (marker-scan, 349 files, all of
game/data): PASS, 0 hits, 1 declared exception."* At `07f8b75`:

```
$ node tools/analysis/marker-scan.mjs ; echo $?
K1 FAIL — 42 hits, 1 declared exceptions ({"F1":0,"F2":42,"F3":0,"F4":0,"F5":0})
1
```

All 42 are `game/data/npcs/quest-givers.json : npcs[N].post.pos` — a file added by W1-07 round 4
*after* the measurement was taken. The tool is honest and its exit code is correct; the claim in
the status file is simply a measurement of a tree that no longer exists. **Rule 12 exists for
exactly this** ("stamp the commit on every number"), and W1-21's `measured` block carries no
commit at all.

Whether the hits are true positives is a judgement someone has to make and nobody has: an NPC's
post is a legitimate world coordinate, *and* F2's intent is that quest data must not carry
coordinates a marker could be drawn from, *and* these are quest **givers**. `marker-scan` has an
exceptions file with a stale-declaration check built for precisely this, and no exception has
been filed. It is a five-minute decision that is currently sitting as a red gate.

## 6. RI-UIX06 — the re-run the handover asked for first, and what it shows

The hand-off's first outstanding item was *"ui-metrics rerun after the BODY=19 and edge-normal
fringe fixes was in flight"*. I ran it. Under a loadavg of 15–30 it is slow; the per-screen
stem measurements are in `reports/runs/UI-METRICS/` and in the raw log cited in the JSON.

The re-run does not just report numbers, it exposes a second instance of §3.3's shape. FD1 and
FD2 — and RI-UIX06's own text calls FD2 *"the check the item says the whole thing turns on"* —
pick their measurement region like this:

```js
const textEls = ui.elements.filter((e) => e.visible && e.text && e.text.length > 40
  && ['book_page','journal_entry','detail_panel','attribute_preview'].includes(e.kind));
```

A hard-coded whitelist of four element kinds. `game/src/ui/screens/progress.js` draws the skills
sheet as `sheet_row` and `attribute_row`, neither of which is on the list, so:

```
sheet   1280x720@1: stem null px (0 samples)
spells  1280x720@1: stem null px (0 samples)
sheet   1280x720@2: stem null px (0 samples)
```

and the grader then does `at(dpr) = out.captures.filter(c => c.stem_transition_device_px !== null)`
— it **silently drops** the screens it could not measure and reports `PASS … over N screens`.
Two of the six screens contribute nothing to the check the item turns on; the map contributes
nothing to any of it, because it is not in `SCREENS`. Three of the build's seven screens have
never had their type fidelity measured.

The book at DPR 2 measures **1.468 device px**, which is the genuinely load-bearing number here
and it is a good one — it is the signature an upscaled canvas cannot produce, and it is real.

## 8. Arbitration

**AR-1 — Souls leakage into the fight: not independently re-measured, and I say so.** The
in-combat non-pause is the AR-1-relevant property here (S14 / RI-UIX03 §A: a menu must **not**
stop a fight) and the builder's own `ui-pause` run records `M-P2 frame delta EXACTLY 120 of 120
in combat` and a roll firing with the screen open. I did not re-run it — the box was carrying 30
to 40 browsers and I spent the browser budget on the map instead. It is recorded as
`not_applicable → no`: it is recorded as **pass, on the builder's evidence, not mine**, and
flagged in `method_deviations`. A later critic should re-run `tools/harness/ui-pause.mjs`.

**AR-2 — Morrowind leakage: FAIL.** The chain, so it can be checked rather than believed:

1. `RI-UIX04` §Scoring: *"Q3, Q6 and Q7 hits additionally trigger **AR-2**."*
2. JU8 is the Q7 row. `AMENDMENT-W1-MAP-01` §3a rewrites it and lists seven hard fails,
   including *"a square for a place the player has not stood in"*, *"terrain rendered where the
   player has not been"*, and *"any API by which a quest can place, request, highlight or name a
   position on the map"*.
3. §3 above demonstrates the first two on the drawn screen and the third on the object.
4. §3c of the same amendment settles the "but nothing calls it" defence in advance: *"a map with
   a `revealLocation(id)` that nothing currently calls is **not** compliant, because the next
   quest author will find it and the check that catches them will be a code review rather than a
   number."*

I have applied S26 honestly and not stretched an AR rule to cover an ordinary defect: the AR-2
status comes from the judged item's own scoring rule, and the underlying problem is also written
up as a defect in its own right in §3.2. If the orchestrator reads the save-file route as
out-of-scope for AR-2, the score does not move — `RI-UIX04` still carries a triggered hard fail
and is still capped at 2 — but the piece would then be FAIL rather than AR-2 FAIL.

**AR-3 — seam sterility: not sterile.** `Engine._recomputeBurden()` makes carried weight a real
speed multiplier (`_burdenMult() → 0.90` with the hauberk and maul on), so the inventory screen
and the traversal system touch. The reading screens also cross into `topicsKnown`. Recorded as
`seam_sterile: false`.

## 10. Biggest gap

**`GAP-W1-ui-map-outside-the-ar2-detectors`** — `ui.hud.minimalism` — **blocking**

Every AR-2 detector this piece ships predates the map and none of them opens it. The only
compliance report that exists for the surface S35 defines by its refusals is the one the map
screen computes about itself, and the structural half of that report is a hand-written list of
three method names that omits the object's fourth mutator — `restore(blob)`, arity 1, which
names places and repaints the raster. A save whose `world.discovery` block is forged in **both**
its fields loads with zero dropped and puts 42 squares on the map, 35 of them for places the
body has never stood in, over a fully rendered province, while the screen reports
`places_drawn == places_discovered` and nothing anywhere goes red.

**Why it matters.** `docs/PLAN.md` §3 makes this piece the enforcement point for the most-cited
arbitration rule in the corpus. After S35 the thing to be enforced moved from the journal to the
map, and the enforcement did not move with it. The amended JU8 lists seven hard fails and the
build tests none of them from outside the map's own code.

**Remedy.**

*Action.* (a) Add the map to every detector: `ui-layer.mjs` `VIEWPOINTS` gains `ui_menu_map` in
both the world and local views; `ui-metrics.mjs` `SCREENS` gains `map`; `ui-forbidden.mjs`'s
declared sweep gains `map`; `marker-diff.mjs` runs its quest-state differential with the map open
as well as closed. (b) Replace the `mutator_arities` literal in `game/src/ui/system.js` with an
enumeration over `Object.getOwnPropertyNames(Object.getPrototypeOf(sim.discovery))`, classifying
by what each method writes, so a mutator nobody remembered is counted. (c) Close `restore()`:
either drop `places` from the save entirely and re-derive it on load from the raster plus the
site radii in `terrain.json sites[].r_flat` — which removes the forgeable field rather than
validating it — or corroborate a loaded place against something the same blob does not carry.
(d) Take `ui-metrics.mjs`'s region selector off its four-kind whitelist so a screen that cannot
be measured is reported as unmeasured rather than filtered out of the median.

*Acceptance.* `ui-layer.mjs`, `ui-metrics.mjs`, `ui-forbidden.mjs` and `marker-diff.mjs` each
visit the map in both views and report 0 undeclared components, 0 forbidden kinds and 0
quest-conditioned elements there; `getUIState().map.mutator_arities` lists **every** state-writing
method on the discovery prototype with **every** arity 0; `ui-metrics.mjs` reports a non-null
stem sample count for **all** screens it opens, or names the screens it could not measure and
fails; and `node tools/harness/critic-w1-21-r1b.mjs` returns **F1, F2 and F3 pass** — a forged
save naming all 42 places over an all-ones raster draws no more place squares than the body has
stood in.

*Targets.* `tools/analysis/ui-layer.mjs`, `tools/metrics/ui-metrics.mjs`,
`tools/analysis/ui-forbidden.mjs`, `tools/analysis/marker-diff.mjs`, `game/src/ui/system.js`,
`game/src/sim/discovery.js`, `game/src/save/state.js`.

## 11. Secondary observations

1. **`journal-ui.mjs` JU8 still implements the pre-S35 clause.** It asserts
   `map_exists === false` and that `openMenu('map')` throws. `AMENDMENT-W1-MAP-01` amended the
   **item** and filed a NOTICE in it; nobody amended the **instrument**. W1-21's recorded
   "RI-UIX04 11/11" cannot be true at HEAD. Whoever lands the amendment owns the tool too.
2. **`ui-forbidden.mjs` has still never been run** against any build. It is the more interesting
   half of RI-UIX01 §B — it has a real pixel probe and a self-test that injects "247" over an
   enemy through the build's own glyph path — and it has a `--declared-only` escape hatch that
   the item predicts will be taken. It also does not open the map.
3. **`UISurface.el()` as the only drawing path is the best structural decision in this piece.**
   It clips the callback to the declared rect, so the census and the pixels cannot disagree —
   which is why §3.1's element-level assertions mean anything at all. It should be defended.
4. **`game/src/render/ui.js` still resizes without `texture.dispose()`.** The builder found and
   fixed the ghost-frame defect in its own surface and flagged the dialogue surface as likely to
   carry the same one. It still does. Not this piece's file; it should be somebody's.
5. `teleport(x, z, opts)` takes two coordinates and an options object. I passed `(x, y, z)`,
   silently teleported the body to `z = ground height`, and lost a run to it. It is at least the
   second probe in this project to make that mistake. A third argument that is an object where a
   number was passed could throw instead.
