# `game/` — wave-1 piece W1-00: harness, determinism and persistence

This is a **static site**. There is no build step required to run it, no network access at
runtime, and Three.js is vendored at `game/vendor/three/`, so a strict CSP that blocks
external hosts changes nothing (`HARNESS.md` R1).

```bash
# serve the repo root over http:// and open /game/index.html — or just run the harness:
node tools/harness/smoke.mjs                                    # environment gate
node tools/harness/run-headless.mjs --scenario cmb-duel-infantry # produce a run directory
node tools/harness/api-probe.mjs                                # RI-MTH01 M1-M7
node tools/harness/determinism.mjs                              # RI-MTH02 R1-R9
node tools/harness/save-audit.mjs                               # RI-JRN05 round trip + hostility
node tools/harness/input-probe.mjs                              # RI-JRN03 desktop input path
node tools/platform/perf-probe.mjs                              # RI-PLT01 Tier-S only
node tools/harness/lint-determinism.mjs                         # HARNESS.md §8, advisory
node tools/analysis/data-index.mjs --check                      # game/data/index.json is current
```

## What is here, and what is deliberately not

**Here.** The fixed 60 Hz simulation and its decoupling from render; the seeded PRNG and the
runtime guard that enforces it; the whole `window.__HARNESS` surface; the
`elder-souls/trace@1` record including the camera channel; the closed 14-button action set
with both a scripted and a real desktop path; IndexedDB persistence with the `RI-JRN05` §A
write protocol; deterministic sky, sun and named weather; the nine viewpoint anchors; and
`game/data/**` in the layout `HARNESS.md` §5 mandates.

**Not here, and declared rather than faked.** Enemy AI, a quest runtime, dialogue, the
province, audio, and every Tier-H performance number. Call `__HARNESS.getCapabilityReport()`
for the machine-readable version of that list with the owning wave-1 piece named for each
gap. Data files that other pieces own carry a `declared_incomplete` block naming the owner
and what is missing. **A method that returned a plausible value without doing the thing
would score −2 under `RI-MTH01` and be treated as measurement fraud under `RI-MTH04`;
a declared gap is neither.**

    sim/

      player.js             the frame machine; every number read from game/data/combat/movesets/
      entities.js           entity instantiation and the two implemented behaviours
      camera.js             the camera rig — INSIDE the fixed step (RI-CAM06 §A)

      events.js             the pooled, closed-vocabulary event bus
    input/
      actions.js            the 14 names. An unknown button throws
      pipeline.js           latching, edges, the 8 f@60 single-slot buffer
      bindings.js           RI-JRN03 §B defaults, matched on KeyboardEvent.code
      real.js               the real desktop path and every §C/§D hazard
    save/

      store.js              IndexedDB, the write protocol, generations, hostility simulation

    render/
      scene.js              the 420 m patch at the origin; deterministic value noise, no PRNG draws

## Three properties worth knowing before you read the code

**1. The determinism guard is a trap, not a convention.** `core/guards.js` replaces
`Math.random`, `Date.now`, `performance.now` and `new Date()`, and *throws* if any of them is
called while a fixed step is executing. The throw propagates out of `stepFrames()`, out of
the harness call, and out of the tool as exit 12. Outside the step they are legal, because
the render path, the save path and the perf instrumentation all need a clock and none of them
can reach a traced value. Three.js's own `Math.random()` (used for object UUIDs) is served by
a separate seeded stream so the whole page is reproducible, not just the simulation.

**2. Simulation time is derived, never accumulated.** `t_ms = frame * (1000/60)`. There is no
`t += 1/60` anywhere, which is why `stepFrames(1)×600` and `stepFrames(600)×1` produce the
same bytes.

**3. The world is a 420 m patch at the origin.** The province coordinates in
`data/world/pois.json` (Thorn at x = 3820, z = 859) are the map wave-1 piece W1-01 builds.
This piece ships the one neighbourhood the twelve canonical viewpoints are posed against,
because those poses are absolute and near the origin and a viewpoint that cannot be shot is a
fail-closed **0** for every fidelity metric it feeds.
