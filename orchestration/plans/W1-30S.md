# W1-30S — the seam pass: make the visual tree safely parallel

Plan-State: satisfied
Parent: [W1-30](W1-30.md) · Contract: [Builder execution contract](BUILDER-EXECUTION-CONTRACT.md)

**One small, fast, behaviour-preserving commit that gives every other visual child a file nobody else
writes to.** This is the only child permitted to touch files it does not own, and it may only *move*
code — never change what a frame looks like.

Dispatch **now**. Everything except W1-30C's API phase and W1-30V waits on it, so it is the critical
path and should be the shortest job in the tree.

## Why this exists

`game/src/render/renderer.js` is the collision point. Today it owns the compositor, the water
reflection target, the VFX prepass ordering and the shadow-fit call. Under the decomposition, A owns
the compositor, B owns lighting and shadows, and H owns VFX and water. Without this pass all three
write to `renderer.js` and reconciling them costs more than they save (directive §4).

And adds three registration points to `renderer.js`:

```js
renderer.registerPrePass(fn)     // H's vfx prepass and water reflection register here
renderer.registerComposite(mod)  // A's composite module installs here
renderer.setLightingFrame(obj)   // B pushes the frame lighting object here
```

After this commit, `renderer.js` belongs to W1-30A alone.

## The bar

**A byte-identical frame.** This pass changes zero pixels.

| gate | acceptance, with units | null control |
|---|---|---|
| frame identity | For all 288 Deck stills and all 12 motion sequences at a fixed seed, the per-frame SHA-256 is **identical** before and after the commit. Not "similar" — identical. | Change one composite constant on a copy (e.g. vignette 0.075 → 0.076); confirm ≥ 90% of frame hashes change. A hash comparison that cannot go red is not a comparison. |
| boot | `node tools/boot-check.mjs` passes; `node tools/check-data.mjs` passes | delete one moved export on a copy; boot-check must fail |
| no behaviour in the move | `git diff` on moved code contains only import/export rewrites and whitespace. Any changed literal, condition or order is a plan violation and is reverted. | reviewer reads the diff; a moved line whose right-hand side changed fails the gate |
| seam liveness | Each of the three registration points has ≥ 1 live registrant after the move, and unregistering it changes the frame. | register nothing; confirm the frame goes wrong in the expected way, then restore |
| library skeleton | `tools/visual/library-census.mjs` runs and reports the current bypass count as the baseline for `regression`. | insert a bare `MeshStandardMaterial` on a copy; census `bypass` must increment |

**Hard fail:** any pixel change, any renamed public symbol without a re-export shim, any moved file
that a non-owner child then has to edit.

## Builder/critic execution allocation

**Builder** — perform the moves; create the empty registries and the contract file; add the three
registration points; run boot/data/content gates; capture the 288 stills and 12 sequences before and
after on the same seed and diff the hashes; run the library census baseline; execute the null control
above on a copy and confirm the hash comparison goes red; write the text report naming every moved
symbol and its new home.

**Fresh critic** — read the whole diff line by line for a behaviour change hidden in a move (this is
the one job that matters here); independently re-capture a sampled 60 stills and 3 sequences on the
GPU pod and re-verify hash identity; confirm each registration point has a live registrant and that
removing it breaks the frame; confirm no other child would need to edit a file it does not own.

## Reuse rows

**Consumed:** the existing `visual-foundation.js` registry shape, `renderer.setVisualFeature`'s
sabotage pattern. **Published:** the four empty registries and `rig-contract.js` — each has its
consumers named in the decomposition table, so the two-consumer rule is satisfied on landing by
declaration and must be satisfied in code by the children that fill them. **Variants:** none; this
pass publishes structure, not content.

## Dependencies and stop conditions

None. Stop only if the frame-hash comparison itself cannot be made deterministic — in which case
**that** is the finding, it blocks the entire visual programme, and it is escalated immediately
rather than worked around, because every gate downstream assumes reproducible captures.

## Falsification audit

The likely failure is a silent behaviour change smuggled in as a tidy-up — a reordered call, a
defaulted parameter, a `const` hoisted past a mutation. The frame-hash gate catches it only if the
captures are genuinely deterministic, which is why the null control on the hash comparison is listed
before the comparison itself. The second risk is over-reach: a builder who "improves" the compositor
while moving it has destroyed the one property that makes this commit safe to land ahead of everyone
else. The critic's first question is therefore *"is there a single changed literal in this diff?"*
